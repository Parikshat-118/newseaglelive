News Eagle Live — Interview Preparation Guide

This guide breaks down your project structurally, logically, and gives you ready-to-use answers for technical interviews.

1. Project Overview & Pitch

The Elevator Pitch:
"I built News Eagle Live, an AI-powered news aggregator and Telegram bot. It automatically fetches global news from various APIs and RSS feeds, uses Large Language Models (like Llama 3) to read, summarize, categorize, and translate those articles, and then stores the processed data in a centralized MySQL database. Finally, a decoupled PHP frontend serves these AI-curated news summaries to users in a clean, modern web interface."

Key Technologies Used

  • Backend Worker: Python 3, apscheduler (for cron jobs), httpx (async HTTP requests)
  • AI Integration: OpenRouter / Groq APIs (using Llama-3 models)
  • Database: MySQL, accessed via SQLAlchemy (Python ORM) and PDO (PHP)
  • Frontend UI: Vanilla PHP, HTML5, CSS3, JavaScript (no heavy frameworks for maximum speed)
  • Deployment: AWS EC2 (Ubuntu), Systemd background services

2. System Architecture

A core strength of your project is its Decoupled Architecture.

  • The Fetcher & Processor (Python): Runs continuously in the background on a Linux server. It reaches out to data sources, downloads raw text, passes it to the AI for analysis, and saves the perfect, formatted result.
  • The Central Brain (MySQL): The database acts as the single source of truth.
  • The Viewer (PHP): The frontend is entirely stateless. It does not fetch news or talk to the AI for the main feed. It simply connects to the database, reads the finalized data, and renders HTML.

Why is this good? If your Python bot crashes, the website stays online and fast. If the website crashes, the Python bot keeps collecting data. This is called Separation of Concerns.

3. Top Interview Questions & Answers

Q1: Why did you decouple the backend (Python) and frontend (PHP) instead of building a single full-stack app in Django or Laravel?
How to answer:

"I wanted a highly resilient, microservices-style architecture. The Python backend is a heavy worker—it manages asynchronous API calls, talks to external AI models, and handles scheduled background jobs. If I combined this with the web server, heavy processing spikes could slow down the website for users. By decoupling them using MySQL as the bridge, the PHP frontend remains incredibly fast and stateless, only having to read data, while Python does the heavy lifting in the background."

Q2: You mentioned this is an AI project. Are you running Machine Learning models locally?
How to answer:

"No, I am not running local neural networks or models like PyTorch on my server. That would require massive, expensive GPU infrastructure. Instead, this is an Applied AI architecture. My Python backend acts as an AI Client. It interfaces securely with powerful cloud-hosted LLMs (like Llama 3.1 70B). I designed the prompts, built the parsing logic (ensuring the AI returns strict JSON), and integrated the AI's output seamlessly into my business logic."

Q3: How do you prevent fetching and processing the exact same news article multiple times?
How to answer:

"I implemented a deduplication system. Whenever the Python adapters fetch a raw article, I take the canonical URL of that article and generate a unique cryptographic hash (SHA-256). Before I send the article to the expensive AI API or the database, I check my database (and Redis cache) for that hash. If it exists, I instantly skip it. This saves API tokens and prevents duplicate data on the frontend."

Q4: How does your new 'Startup Ideas' feature work technically?
How to answer:

"It’s a scheduled pipeline. Every morning, the Python scheduler triggers a specific job. The bot looks at the trending news stored in the database. It constructs a highly strict system prompt for the AI, injecting the news context, and mandates that the AI responds in a precise JSON schema containing 5 to 10 startup ideas, with strict word limits for the titles. Once the JSON is returned, Python validates the structure, parses it, and inserts it into specialized startup_generations and startup_ideas relational tables. The PHP frontend then queries these tables to display daily inspirations to students."

Q5: What happens if the AI provider's API goes down or returns bad data?
How to answer:

"I built fallback mechanisms. First, for API outages, my Python service catches timeout and connection exceptions, logs the error, and gracefully skips that article without crashing the whole bot. Second, if the AI hallucinates and returns broken JSON, I use regex and string manipulation to attempt to strip out markdown fences and extract the JSON object. If parsing completely fails, it iterates to a fallback model or aborts the operation safely."

Q6: What is SQLAlchemy and why did you use it instead of raw SQL queries?
How to answer:

"SQLAlchemy is an Object-Relational Mapper (ORM) for Python. Instead of writing raw INSERT INTO string queries, I define my database tables as Python Classes. This does three things: it prevents SQL Injection attacks by automatically sanitizing inputs, it makes the codebase much cleaner and object-oriented, and it abstracts the SQL dialect, meaning I could easily migrate from MySQL to PostgreSQL in the future with almost no code changes."

4. How to discuss future improvements

Interviews love candidates who know how to improve their own work. If asked "What would you add next?", you can say:

  • Vector Search / RAG: "I would like to integrate a vector database (like Pinecone) to create embeddings for all news articles. This would allow users to do semantic 'smart searches' instead of just keyword searches."
  • User Personalization: "I plan to add a feature where users can upvote/downvote articles, and I can feed those preferences back into an AI prompt to generate a personalized daily digest for them."
